핀빅스 허브비공식 학생 프로젝트

문의 · 신고

최종 갱신 2026년 8월 25일 (제1판)

학사 문의는 대학으로 접수해 주십시오. 수강신청, 장학금, 학적, 등록금, 채용 결과, 시설 이용에 관한 문의는 상명대학교의 해당 담당 부서로 연락해야 합니다. 핀빅스 허브는 비공식 학생 프로젝트이며 대학의 공식 문의 창구가 아니고, 학사 사안에 답변하거나 처리할 권한이 없습니다.

  4. 접수 후 처리 절차와 기한
  5. 버그 신고에 포함할 정보
  6. AI 요약 오류 신고
  7. 접근성 개선 요청
  8. 신고 양식

현재 서비스의 유일한 접수 창구는 GitHub 저장소의 공개 Issues이며 누구나 열람할 수 있습니다. 별도의 이메일이나 비공개 증빙 접수 창구는 운영하지 않습니다. 대상 항목의 제목과 원문 URL, 요청하는 권리의 종류, 공개 가능한 사유만 작성하고 개인정보, 신분증, 증명서, 계약서 등 민감한 자료는 제출하지 마십시오.

2. 개인정보를 적지 마십시오

GitHub Issues는 전 세계에 공개되는 게시판이며 검색엔진에 수집될 수 있습니다. 이름, 학번, 전화번호, 이메일 주소, 주소, 로그인 정보, 재학증명서 등 개인정보와 신원 자료를 작성하지 마십시오. 화면 캡처를 첨부할 때는 개인정보가 표시된 영역을 가려 주십시오.

운영자는 공개 이슈에 개인정보가 포함된 것을 확인하면 작성자에게 GitHub의 편집 또는 삭제 기능을 이용하도록 안내하고, 프로젝트가 관리할 수 있는 범위에서 해당 정보의 재노출을 방지합니다. 운영자는 이용자가 작성한 이슈를 비공개로 전환할 수 없고, 이미 공개된 정보의 검색엔진 색인이나 제3자 복사본까지 회수할 수 없습니다.

3. 권리침해 신고(저작권·명예·사생활)

서비스에 표시된 항목으로 자신의 권리가 침해되었다고 판단하는 경우, 다음과 같이 공개해도 되는 최소 정보만 제출하십시오. 권리침해 가능성이 구체적으로 확인되면 운영자는 본인확인 자료를 공개로 요구하지 않고 우선 표시 중단 여부를 검토합니다.

  • 대상 항목의 원문 URL과 서비스 화면에 표시된 제목
  • 침해된다고 판단하는 권리의 종류
  • 공개 가능한 범위의 요청 사유와 원하는 조치
  • 권리 관계를 확인할 수 있는 공개 웹페이지가 있는 경우 그 URL(선택)

비공개 자료가 없으면 최종적인 권리관계를 확인하기 어려운 사안은 분쟁 판단을 확정하지 않고 표시 중단 상태를 유지할 수 있습니다. 원문 삭제나 법적 판단이 필요한 경우에는 원문 게시 기관, 법원 또는 관계 기관의 절차를 이용해야 합니다.

운영자는 원문을 복제하고 있지 않으므로, 조치는 서비스 화면에서의 표시 중단과 공개 데이터에서의 제거를 의미합니다. 원문 자체의 삭제는 해당 게시물을 게시한 기관에 요청하셔야 합니다.

권리 침해 여부를 판단하기 어렵거나 이해당사자 간에 다툼이 예상되는 경우, 운영자는 해당 정보에 대한 접근을 30일 이내의 기간 동안 임시적으로 차단할 수 있습니다. 절차의 상세는 저작권 및 권리 정책 제7조와 이용약관 제10조에서 정합니다.

관련 법령 「저작권법」 제103조(복제·전송의 중단), 「정보통신망 이용촉진 및 정보보호 등에 관한 법률」 제44조의2(정보의 삭제요청 등)

4. 접수 후 처리 절차와 기한

  1. 접수 확인: 운영자가 요청을 확인하고 접수 사실을 알립니다.
  2. 검토: 대상 URL과 공개 가능한 사유를 확인합니다. 개인정보나 비공개 증빙은 요청하지 않습니다.
  3. 조치: 표시 중단, 데이터 정정, 코드 수정 등 필요한 조치를 수행하고 배포합니다.
  4. 회신: 조치 결과와 사유를 요청인에게 알리고, 저장소의 변경 이력에 기록을 남깁니다.
요청 유형처리 목표
권리침해·개인정보 삭제확인 즉시 조치. 대상과 침해 가능성을 구체적으로 확인할 수 있는 요청은 지체 없이 표시를 중단합니다.
데이터 오류 정정확인 후 다음 자동 수집 주기(하루 2회) 또는 그 이전에 반영
기능 오류·접근성재현 확인 후 순차 수정. 진행 상황은 해당 이슈에 기록합니다.
일반 질의운영자의 학업 일정에 따라 회신이 지연될 수 있습니다.

이 서비스는 상근 인력이 없는 학생 개인의 비영리 프로젝트이므로, 권리침해와 개인정보에 관한 요청을 최우선으로 처리하고 그 밖의 요청은 순차적으로 처리합니다. 처리 결과에 만족하지 못하는 경우 개인정보 처리방침 제15조에 안내된 외부 구제 기관에 도움을 요청할 수 있습니다.

5. 버그 신고에 포함할 정보

  1. 문제가 발생한 화면과 재현 순서
  2. 브라우저 이름과 버전, 운영체제
  3. 문제가 된 공지의 원문 URL
  4. WebGPU 사용 여부(AI 기능 관련인 경우)
  5. 오류 메시지 또는 개인정보를 가린 화면 캡처

6. AI 요약 오류 신고

AI 요약과 후속 질문 답변은 이용자 기기에서 실행되는 생성형 인공지능이 생성한 결과물이며 사실과 다를 수 있습니다. 오류를 신고할 때는 생성된 문장만 보내지 말고, 요약에 사용된 공지의 제목과 원문 URL, 그리고 입력한 질문을 함께 알려 주십시오. 그래야 운영자가 프롬프트나 입력 데이터의 문제인지 모델 자체의 한계인지 구분할 수 있습니다.

생성 결과는 기본적으로 이용자 기기에서 처리되며 운영자에게 자동 전송되지 않습니다. 다만 이용자가 음성 읽기나 공유 기능을 실행하면 결과가 브라우저, 운영체제의 음성 합성 기능, 선택한 공유 대상 또는 클립보드로 전달될 수 있습니다. 이용자가 신고 내용으로 직접 제출하지 않는 한 운영자는 생성 결과를 알 수 없습니다. 모델 파일 자체의 문제는 Transformers.js 또는 모델 저장소에도 함께 신고할 수 있습니다(라이선스 제3조 참조).

7. 접근성 개선 요청

운영자는 장애가 있는 이용자가 장애가 없는 이용자와 동등하게 서비스에 접근·이용할 수 있도록 키보드 조작, 화면 낭독기용 대체 텍스트와 상태 알림, 색상 대비, 움직임 줄이기 설정을 유지하고 있습니다. 이용에 불편을 겪으신 경우 사용하시는 보조기기와 브라우저를 함께 알려 주시면 우선하여 개선하겠습니다.

관련 법령 「장애인차별금지 및 권리구제 등에 관한 법률」 제21조(정보통신·의사소통 등에서의 정당한 편의제공의무)

8. 신고 양식

아래에서 유형을 선택하면 해당 양식이 준비됩니다. GitHub Pages에서 열람 중인 경우 이슈 등록 링크가 함께 표시됩니다.



GitHub에 신고 등록

GitHub Pages에 게시되면 현재 저장소의 이슈 링크가 자동으로 표시됩니다.

이 양식은 공개 GitHub Issues에 게시됩니다. 이름, 연락처, 신분증, 증명서, 계약서, 실제 개인정보 값 등 개인정보나 비공개 자료를 입력하지 마십시오. 공개 자료만으로 즉시 확인하기 어려운 권리분쟁은 표시 중단 상태를 유지한 채 관계 기관의 절차를 안내할 수 있습니다.
